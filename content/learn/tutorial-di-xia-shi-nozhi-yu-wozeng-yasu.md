## 2. 圧力ボタンのスクリプティング

Q&A (0)

クライブの地下室の第 1 レベルでは、圧力ボタンと呼ばれる別の種類のボタンの上に彫像を移動させました。圧力ボタンは、ドアが開いたままになるために一定の圧力を必要とします。クライブが自分で押そうとすると、ボタンから飛び降りると同時にドアが閉まってしまいます。

このレベルの 3 番目の部屋には、PressureButton という名前のボタンがありますが、これをスクリプトにして圧力ボタンとして機能させます。彫像がそのボタンを押し続けると、ドアが開き続けます。

開始するには：

**1.**PressureButton に Script Machine を追加します。

**2.**[FirstDoorScript を SecondDoorScript にコピーしたときと同じ手順で、DoorButtonScript をコピーし、PressureButtonScript に名前を変更します。](https://learn.unity.com/tutorial/custom-events-in-visual-scripting#605c9c1cedbc2a158dff82e5)

**3.**PressureButtonScript を新しい Script Machine にアタッチします。

#### 引数を持つイベント

これまでの DoorButton は、一度開くとずっと開いたままになります。PressureButton は、ボタンが押されるとドアが開き、ボタンが押されないとドアが閉じるという異なる動作をします。開閉のための 2 つのイベントを作る代わりに、カスタムイベントに渡される Boolean の引数を持つ 1 つのイベントを作ることができます。

**1.**PressureButtonScript で、Custom Event: Trigger ユニットを見つけ、名前を PressureButtonPushed に変更します。

**2.**ユニットのヘッダーで、Arguments を 0 から 1 に変更します。**Arg.0** と書かれた新しい入力が表示されます。

**3.**この引数に True を入力するとドアが開き、False を入力するとドアが閉じます。

#### タスク：3 つ目の部屋を完成させる

あなたのタスクは、圧力ボタンと 3 つ目のドアのスクリプティングです。必要なユニットはおなじみですが、論理といくつかの設定だけが異なります：

**1.**DoorToOpen 変数を GameObject ThirdDoor に変更します。

**2.**スーパーユニットを使ったアニメーションは、通常のボタンと同じですが、閉じるためには Animation Value の False を送信します。

**3.**SecondDoorScript を ThirdDoorScript にコピーして、ThirdDoor にアタッチします。

**4.**PressureButtonPushed イベントから渡される Boolean 値に応じて開閉するように ThirdDoorScript を編集します。

これは自分でできることです。ヒントが必要な場合や行き詰まった場合は、Samples サブフォルダにあるビジュアルスクリプトファイルを参照してください：

- Completed PressureButtonScript: **Final_PressureButtonScript**
- Completed ThirdDoorScript: **Final_ThirdDoorScript**

**注意：**これらのファイルで使用されているスーパーユニットはサンプルコピーであり、あなたが作成したスーパーユニットのビジュアルスクリプトではありません。

## 3. トグルレバーのスクリプティング

Q&A (0)

このレベルの 4 番目の部屋には、ゲームの最初のレベルで使用したレバーのようなものがあります。この制御はトグルで、クライブがセルの中に入るとオンになり、もう一度セルの中に入るとオフになります。

次のタスクは、このレベルの 4 番目の部屋にあるレバーをスクリプティングすることです。ここでは、いくつかのポイントをご紹介しましょう：

- レバーに必要なユニットのうち（このチュートリアルで）まだ使っていないのは、Boolean 値を反対の値に切り替える **Negate** だけです。
- イベントは、クライブがセルに入ったときにトリガーされなければなりません。
- トラップドアは開いた状態で始まります。
- スーパーユニットを使うと、ドアやボタンに使用したのと同じようにレバーのアニメーションを制御することができます。エラーが発生します。**Null Check**ユニットを使ってそれを追跡し、修正します。推理力を発揮して、先を見ずにやってみてください。
- TrapDoor ゲームオブジェクトは、1 つの Boolean 引数を持つ LeverSwitched という名前のイベントを使用して、すでにスクリプティングされています。

TrapDoorLever（**ObjectRoot > TrapDoorLever**）という名前のゲームオブジェクトを見つけ、TrapDoorLeverScript という名前で、この制御をスクリプティングするための新しい Script Machine を作成します。

ヒントが必要な場合や行き詰まった場合は、Samples サブフォルダーにあるビジュアルスクリプトファイルを参照してください：

- Completed TrapDoorLeverScript: **Final_TrapDoorLeverScript**
- Updated AnimAndFX super unit: **Super_2**

**注意：**Final_TrapDoorLeverScript で使用されているスーパーユニットは、サンプルコピーであり、作成したスーパーユニットのビジュアルスクリプトではありません。

## 4. VFX のオプション化（super unit update #2）

Q&A (0)

## 5. ボーナスポイント：オーディオの追加 (super unit update #3)

Q&A (0)

スーパーユニットにオーディオのオプションを簡単に追加することができます。その方法とは、スーパーユニットがゲームオブジェクト Self をチェックして、AudioClip という名前の Object 変数があるかどうか、Type が AudioClip であるかどうかを調べます。もし存在していれば、それを取得します。それが Null の場合（None に設定されているかもしれない）、何もしません。Null でなければ再生します。

必要な追加ユニットは：

- **Has Variable：**このユニットを使って、変数 AudioClip が存在するかどうかを確認する
- **Audio source: Play clip at point：**このユニットは、ワールド空間のある場所でクリップを再生する。Transform: Position ユニットで Self の位置を指定する。

このスーパーユニットを追加することで、AnimAndFX スーパーユニットをビジュアルスクリプトに含む任意のゲームオブジェクトに AudioClip という名前の Object 変数を定義し、その変数を再生したい使用可能なクリップに設定することができます。また、Has Variable ユニットは、その変数が存在しないかどうかをチェックするので、このスクリプトのビットによって AudioClip 変数がない状態でスーパーユニットを実行する既存のゲームオブジェクトでエラーが発生することはありません。

完成したスクリプトを見るには、Samples サブフォルダーの**Super_3**を参照してください。
