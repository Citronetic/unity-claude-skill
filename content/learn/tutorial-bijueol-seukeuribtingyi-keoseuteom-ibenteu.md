프로그래밍에서 이벤트는 사건을 의미합니다. 즉 어떤 일이 발생한다는 뜻입니다. 이벤트를 사용하면 '이 상황에는 저렇게 하라'는 방식의 게임플레이 메카닉을 설계할 수 있습니다. 비주얼 스크립팅에서는 단 두 개의 유닛으로 커스텀 이벤트를 사용할 수 있으며, 이 프로세스는 C#에서보다 훨씬 쉽습니다. 이 튜토리얼에서는 커스텀 이벤트를 사용하여 고양이 클라이브를 위한 상황을 만들어 보겠습니다.

이 튜토리얼에서 배울 내용은 다음과 같습니다.

- 비주얼 스크립트에 새 커스텀 이벤트 트리거를 추가합니다.
- 커스텀 이벤트에 반응하는 비주얼 스크립트를 작성합니다.
- 커스텀 이벤트를 통해 한 스크립트에서 다른 스크립트로 게임 오브젝트를 전달합니다.
- 프로젝트 창에서 비주얼 스크립트를 복사합니다.
- 비주얼 스크립트를 다른 목적에 맞게 조정합니다.
- 기존 슈퍼 유닛에 데이터 입력을 추가합니다.

## 1. 개요

Q&A (0)

**이벤트**는 프로젝트에서 스크립트로 감지하고 그에 따른 행동을 취할 수 있는 일의 발생을 가리킵니다. 사용자 입력, 콜라이더 충돌, 특정 위치를 향한 플레이어 이동 등이 있으며 그 외에도 많은 이벤트가 있습니다.

이벤트를 방송 메시지와 비슷한 것으로 생각해 보겠습니다. 비주얼 스크립팅에서 **이벤트 유닛**은 이러한 메시지의 수신기 역할을 하며, 이벤트에 대응하여 동작이 발생하도록 스크립트를 시작합니다. 이벤트 유닛으로는 새로운 게임 오브젝트 컴포넌트 스크립트에서 볼 수 있는 Start와 Update 유닛, 그리고 앞서 클라이브의 셀 진입을 제어하기 위해 사용한 스크립팅된 이벤트를 예로 들 수 있습니다.

이 튜토리얼에서는 게임 오브젝트가 서로 상호 작용하도록 커스텀 이벤트를 포함하는 스크립트를 작성합니다. 이벤트는 언제 어떤 일이 발생하는지를 제어할 수 있는 강력한 프로그래밍 툴입니다.

## 2. 버튼을 사용하여 문 열기

Q&A (0)

FirstDoor를 통과한 클라이브는 셀 중 하나에 버튼이 있는 새 방에 들어가는데, 이 게임 오브젝트는 DoorButton입니다. 이 방에서 클라이브가 DoorButton을 눌러야 문을 열 수 있도록 SecondDoor 문을 프로그래밍해 보겠습니다.

클라이브가 접근할 때까지 열리지 않는 이전의 문과는 달리, 이 문은 클라이브가 DoorButton을 누르는 즉시 열려야 합니다.

이렇게 하려면 커스텀 이벤트를 사용하여 클라이브가 버튼을 눌렀을 때 이를 감지하도록 해야 합니다. DoorButton의 스크립트는 버튼이 눌렸을 때(클라이브가 셀에 들어갈 때) 이벤트를 호출하고, SecondDoor의 스크립트는 문을 여는 시퀀스를 실행하여 이벤트에 즉시 반응하게 됩니다.

## 3. 버튼의 커스텀 이벤트 트리거 스크립트 작성

Q&A (0)

DoorButton에 이벤트 트리거를 만들고 작업을 시작해 보겠습니다.

**1.**계층 구조에서 **ObjectRoot > DoorButton**을 선택하고 새 Script Machine을 추가한 다음, 비주얼 스크립트의 이름을 DoorButtonScript로 지정합니다. 그런 다음 **Assets > VisualScriptingTutorial > Tutorial > VisualScripts**에 저장합니다.

**2.**Start와 Update 유닛이 있는 경우 삭제합니다.

**3.**Moving Object가 셀에 들어올 때 트리거되는 이벤트를 감지하고 처리할 수 있도록 **Enter Cell** 이벤트 유닛을 추가합니다.

**4. Trigger Custom Event** 유닛을 추가하여 새로운 커스텀 이벤트를 만들고 이름을 **DoorButtonPushed**로 지정합니다. 이 유닛이 문의 스크립트에 '방송 메시지'를 보내게 됩니다.

**5.**Custom Event Trigger 유닛을 살펴봅니다. 기본적으로 Self로 설정되는 게임 오브젝트 입력부가 있는데, 이 경우에는 DoorButton이 그에 해당합니다. 하지만 이 이벤트의 수신 측에서 스크립트에 필요한 것은 버튼이 아니라, 열어야 하는 문입니다. Object 변수를 사용하여 SecondDoor 게임 오브젝트를 이 이벤트 유닛에 전달하게 됩니다. 커스텀 이벤트를 사용하면 슈퍼 유닛의 경우와 마찬가지로 수신 스크립트에 값을 전달할 수 있습니다.

**6. DoorToOpen**이라는 Object 변수를 만들고 Type은 **GameObject**로, **Value**는 SecondDoor 게임 오브젝트로 설정합니다. 그런 다음 이 유닛을 Custom Event Trigger의 입력부에 연결합니다. **팁:**계층 구조에서 SecondDoor를 드래그할 수 있습니다.

**팁:** 이 Object 변수는 인스펙터에 나타나므로, 여러분이나 프로젝트에 참여하는 다른 개발자가 이 버튼으로 열 수 있는 다른 문을 쉽게 선택할 수 있을 것입니다. 다음 단계에서 만들 스크립트와 같이, 문에 이벤트용 스크립트가 포함되어 있는지 확인하세요.

## 4. 비주얼 스크립트 복사

Q&A (0)

이제 SecondDoor 스크립트를 작성하겠습니다. 기존 작업물을 바탕으로 작성할 수 있도록 FirstDoorScript의 스크립트를 조정할 것입니다.

**1.**프로젝트 창에서 VisualScripts 폴더로 이동하고 Ctrl+D / Cmd+D를 사용하여 FirstDoorScript를 복제합니다.

**2.**복사본의 이름을 SecondDoorScript로 변경합니다.

**3.**계층 구조에서 **ObjectRoot > SecondDoor**를 선택하여 컴포넌트를 인스펙터에 표시합니다.

**4.**프로젝트 창에서 새 파일 SecondDoorScript를 Script Machine 컴포넌트의 Graph 프로퍼티로 드래그하여 BaseDoorScript를 대체합니다.

이제 이 스크립트를 새로운 게임 메카닉에 적용할 수 있습니다.

## 5.  문에 대한 커스텀 이벤트 스크립트 작성

Q&A (0)

**1.**이 스크립트에는 Object 변수 IsOpen이 필요합니다. Blackboard의 Object 탭을 사용하여 SecondDoor에 IsOpen 변수를 추가하세요.

**2.**이 새 문에 적용되지 않는 두 가지 유닛 세트가 있습니다.

- 열쇠를 확인하는 유닛
- 클라이브가 지나간 문을 닫는 유닛(문이 닫히면 다시 들어갈 수 없음)

스크립트에서 이러한 유닛을 삭제합니다. 그러면 다음과 같은 항목이 남게 됩니다.

[Image: image]

이 비주얼 스크립트에는 두 가지 이벤트에 대한 플로가 필요합니다. 감지할 첫 번째 이벤트는 클라이브가 문을 건너가려고 할 때입니다. 이전에 본 것처럼 스크립트는 클라이브가 문을 통과하도록 하거나 클라이브의 이동을 취소합니다. 이 이벤트 플로는 완료되었습니다.

감지할 두 번째 이벤트는 버튼이 눌렸을 경우입니다. 이 이벤트가 발생하면 DoorButtonScript는 DoorButtonPushed 이벤트를 트리거합니다.

**3.**이 이벤트를 감지하기 위해 **Custom Event** 유닛을 추가하고 DoorButtonPushed라는 이름을 입력합니다.

**4.**이벤트를 스크립트에 연결하여 이벤트가 감지되면 문이 열리도록 합니다.

**5.** 작업을 저장합니다(**Ctrl + S/Cmd + S**).

**6.** 플레이 테스트를 해 봅니다. Values 버튼이 활성화된 상태로 Script Graph 창을 열어 두고, 두 이벤트가 트리거되는 모습을 확인합니다.

그래프는 아래 이미지와 같아야 합니다.

[Image: image]

이제 클라이브가 버튼을 누르면 문이 즉시 열립니다.

## 6. 버튼 애니메이션화(슈퍼 유닛 업데이트 #1)

Q&A (0)

이제 이벤트가 작동하니 버튼으로 돌아가 애니메이션과 효과를 추가해 보겠습니다. 스크립트는 다음과 같습니다.

[Image: image]

스크립트가 익숙해 보이지 않나요? AnimAndFX 슈퍼 유닛과 비슷하게 생겼습니다. 이 레벨에는 버튼이 하나만 있는 것이 아니므로 슈퍼 유닛을 개선하여 문뿐만 아니라 버튼에도 사용할 수 있도록 하겠습니다.

현재 슈퍼 유닛 비주얼 스크립트는 다음과 같습니다.

[Image: image]

이 두 스크립트의 메인 유닛에서 유일한 차이점은, 버튼에 대한 애니메이션에는 Pushed라는 이름의 파라미터가 필요하고 문에 대한 애니메이션에는 Opened라는 이름의 파라미터가 필요하다는 것입니다. 그러한 파라미터를 지정할 수 있도록 이 슈퍼 유닛에 다른 데이터 입력을 추가해 보겠습니다.

슈퍼 유닛을 업데이트하는 단계는 다음과 같습니다. 빠르게 편집하는 방법도 같이 살펴보겠습니다.

**1.**먼저 DoorButtonScript에 슈퍼 유닛을 추가한 다음, 더블 클릭하면 편집할 수 있습니다.

**2.** **Animation Name**이라는 새 입력을 만들고 Type을 String으로 지정합니다. **팁:** Graph Inspector에서 **Data Inputs**를 드래그하여 Animation Name이 맨 위에 오도록 순서를 변경할 수 있습니다.

업데이트된 슈퍼 유닛은 아래 이미지와 같아야 합니다.

[Image: image]

**3.**DoorButtonScript로 돌아갑니다(Script Graph 창 메뉴 표시줄의 왼쪽 끝에 있는 **DoorButton**을 선택).

**4.**클라이브가 셀에 들어갈 때 버튼을 누르는 애니메이션을 추가하도록 DoorButtonScript를 업데이트합니다. 이때 애니메이션 'Pushed'를 사용합니다.

**5.**클라이브가 셀을 나갈 때 버튼 눌림을 해제하는 애니메이션을 더 추가합니다.

업데이트된 DoorButtonScript는 아래 이미지와 같아야 합니다.

[Image: image]

이렇게 변경하고 나면 FirstDoorScript와 SecondDoorScript를 업데이트해야 합니다. 'Opened'는 원래 슈퍼 유닛에 하드 코딩된 파라미터지만 이제 슈퍼 유닛을 포함하는 각 비주얼 스크립트에 지정되어야 합니다.

작업을 반드시 저장하세요. 그런 다음 레벨을 플레이하고 클라이브로 처음 두 개의 방을 통과해 보세요. 두 번째 방에 있는 버튼이 눌렸다가 다시 올라올 것입니다. 빛나는 시각 효과가 버튼이 '켜짐' 상태임을 계속 알려 줍니다. 버튼이 눌리면 곧바로 문이 열립니다.

힌트가 필요하거나 진행이 막히면 Samples 하위 폴더에서 다음 비주얼 스크립트 파일을 참조하세요.

- 업데이트된 AnimAndFX 슈퍼 유닛: **Super_1**
- 완성된 DoorButtonScript: **Final_DoorButtonScript**
- 업데이트된 FirstDoorScript: **Final_FirstDoorScript**
- 업데이트된 SecondDoorScript: **Final_SecondDoorScript**

**참고:** 이 파일에 사용된 슈퍼 유닛은 샘플 복사본이며, 사용자가 만든 슈퍼 유닛 비주얼 스크립트가 아닙니다.

## 7. 다음 단계

Q&A (0)

클라이브는 이제 이벤트 덕분에 지하실에 있는 두 개의 방을 통과할 수 있습니다. 빌트인 이벤트, C#으로 작성된 커스텀 이벤트, 비주얼 스크립팅에서 만든 커스텀 이벤트를 사용했습니다. 한 게임 오브젝트에 발생한 일이 다른 게임 오브젝트에 영향을 주거나, 플레이어의 점수 또는 대미지를 수정하거나, 다른 조건을 변경하는 많은 상황에서 이벤트를 사용할 수 있습니다.

다음 튜토리얼에서는 상태 머신에 대해 배울 것입니다. 상태 머신을 활용하면 이벤트를 더 효과적으로 사용하고, 게임플레이를 원하는 만큼 복잡하게 만들 수 있습니다. 그러나 먼저 클라이브가 제어할 수 있는 몇 가지 장치를 비주얼 스크립팅하여 더 많은 기능과 효과를 지하실에 추가해 보겠습니다.
