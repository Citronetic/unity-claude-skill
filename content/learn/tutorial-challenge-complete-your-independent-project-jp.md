## 1. 概要

Q&A (0)

これで、**Creative Core: Prototyping** の学習体験は終了です。**Creative Core** パスウェイを完了した方は、その完了も間近です！

最後の実践課題として、複数のクリエイティブ分野で学んだことを応用し、作成した基本のプロトタイプに磨きをかけます。これが、あなたの自主プロジェクトとなります。

最終的な自主プロジェクト投稿のためのすべての基準をここで確認することになります。Creative Core: Prototyping の小テストと 2 つの短いチュートリアルを完了した後、**Creative Core** パスウェイの最後の段階でプロジェクトを投稿することができます。

**重要：Creative Core** パスウェイをすべて完了していない場合、このプロジェクトを完了するために必要な経験値にギャップがあることがわかります。そのような場合は、未完了のミッションを完了することが可能です。詳しくはこちらをご覧ください。

## 2. 洗練されたプロトタイプ例の見直し

Q&A (0)

自分自身の洗練されたプロトタイプに取り組む準備をするために、**Creative Core: Prototyping**の学習体験の最初にプレビューしたウォーキングシミュレーターの例を、時間をかけて見直してみましょう。見直しながら、以下を確認します：

- 自分の作業をする前にレビューした改良済みのプロトタイプをもとに、どのように作るのかをおさらい。
- [Creative Core の各分野](https://learn.unity.com/tutorial/welcome-to-creative-core?missionId=61a64fafedbc2a0021b4614d&pathwayId=61a65568edbc2a00206076dd&contentId=61a65097edbc2a0021b4619b#619faf11edbc2a2b379d4b14)が全体的な体験に与える影響。

サンプル例の確認方法：

**1.**  Unity エディターで **Creative Core: Prototyping** プロジェクトを開きます。

**2.**  Project ウィンドウで、**Assets > CreativeCore_Prototyping > Scenes** の順に進みます。**4-FinalLook** シーンを開きます。

**3.**  Scene ビューでシーンを見直します。

**4.**  **Play** を選択すると、Play モードになり、プロトタイプを探索することができます。終了したら、忘れずに Play モードを終了してください。

## 3. 最終的なアセットのインポート

Q&A (0)

プロトタイプが完成したら、洗練された体験で使用する最終的なアセットを追加することができます。

記憶を呼び覚ます必要がある場合は、以下の手引きを確認し、このプロセスに役立てることができます：

- [Unity Asset Store からアセットをダウンロード](https://learn.unity.com/tutorial/project-setup-processes#60ed7a86edbc2a002520b6f4)し、プロジェクトにインポートします。
- コンピューターから[個々のアセットをインポート](https://learn.unity.com/tutorial/project-setup-processes#60ed7aa2edbc2a002096b764)します。
- [ローカルアセットパッケージのインポート](https://learn.unity.com/tutorial/project-setup-processes#60ed7a91edbc2a002096b762)

#### プレースホルダーを残しておく？

また、特定の最終的なアセットを調達または作成できない場合、独立したプロジェクトでアセット用のプレースホルダーを使い続けてもかまいません。ただ、次のことを忘れないでください：

- このことがユーザー体験に与える影響を評価し、それに応じてプロトタイプをユーザーに紹介します（たとえば、プロジェクトのポートフォリオの書き込みでこのことを明確にします）。
- サードパーティのプレースホルダーアセットは、そのライセンスに従って使用し、必要に応じて他のクリエイターに帰属させ、クリエイターとしての[知的財産のグッド・プラクティス](https://learn.unity.com/tutorial/copyright-for-creators)に従います。

## 4. Creative Core の体験を集約する

Q&A (0)

基本的なプロトタイプができたので、独立したプロジェクトの基礎ができ、より洗練された体験に変える準備が整いました。

他のパスウェイを完了した方は、**Creative Core**パスウェイの中心となる芸術的な各分野を取り込む準備が整っています。**Creative Core: Prototyping** を独自に始めた方は、このチャレンジで知識のギャップを確認したり、既存の理解を定着させる良い機会です。

以下のようなそれぞれの分野を使用して、作成した体験をより良いものにする必要があります：

- シェーダーとマテリアル (Shaders and Materials)
- ライティング (Lighting)
- アニメーション (Animation)
- VFX
- カメラ (Cameras)
- ポストプロセス (Post-processing)
- オーディオ (Audio)
- UI

#### 先ずは、追加のフィードバックが必要ですか。

プロトタイプのユーザーテストができなかった場合、他の **Creative Core**分野をプロトタイプに適用する前に、より多くのフィードバックが必要かもしれません。[プロトタイププロジェクトを WebGL ビルドで公開](https://learn.unity.com/tutorial/create-and-publish-webgl-builds)し、[Unity Learners グループ](https://learn.unity.com/learn/g/unity-learners?tab=discussion)で共有することでフィードバックを得ることができます。

**ヒント：**

- 背景を説明し、**Creative Core**パスウェイの一環としてこのプロトタイプを作成したことを記載します。
- プロトタイプの特定の機能についてのフィードバックを求めている場合は、それを明記することで、焦点を絞ったフィードバックが得られます。
- プロトタイプのレビューに時間を割いてくれたり、丁寧なフィードバックをくれたりする他のコミュニティのメンバーには、必ずお礼を言うようにしましょう！また、グループに投稿された他の人の作品をレビューすることで、コミュニティに貢献することができます。

## 5. 自主プロジェクトの基準

Q&A (0)

この自主プロジェクトは、クリエイターとしての自分のニーズを満たすものであるべきですが、**Creative Core**パスウェイ全体のキャップストーンとなるチャレンジでもあります。このステップでは、チャレンジのハイレベルな成功基準の概要を説明し、次のステップでは、各クリエイティブ分野の具体的な内容について詳しく説明します。

自主プロジェクトについて：

- グレーボックスの段階から改良を加えたプロトタイプをベースにしていること。提供されたリソースを使って作成したウォーキングシミュレーター（コーディング経験のない方向け）でも、技術力のある方ならお好きなコンセプトで作成することができます。
- コンセプトに合わせて Unity の中核となる各クリエイティブシステムを活用し、具体的な実践場面でのスキルとその活用能力をアピールしてください。
- シェーダーやマテリアルの効果的な使用、ライティング、 ポストプロセス (後処理用) エフェクトにより、基本的なビジュアルレベルを達成することができます。
- 自主プロジェクトの設計目標を達成したこと、重要なインタラクションと機能が期待通りに機能していることを確認するためにテストを受けてください。

このチャレンジには、少なくとも 8 時間を費やすことを想定しておく必要があります。

**重要：**ほとんどの場合、**Creative Core** パスウェイのすべてのミッションが、あなたのプロジェクトにある程度適用されます。これは、あなたができることを示すチャンスであることを忘れないでください。

## 6. 各領域におけるガイドライン

Q&A (0)

以下の機能については、それぞれの説明を参照しながらプロジェクトに取り組んでください。プロトタイプのビジュアルをどこまで磨き上げるかは、それぞれの状況によって異なりますが、磨き上げたプロトタイプにこれらを取り入れることで、最終的な体験に大きな変化をもたらすことができます。

#### シェーダーとマテリアル

プロジェクトでモデルやその他のオブジェクトを計画する際に、どのようにするかを考えてください：

- インポートしたオブジェクトのマテリアルを変更し、カスタマイズすることができます。
- 地面、床、壁、家具など、環境中のサーフェスのマテリアルを探したり、作成したりします。
- 大切なオブジェクトには、キラキラとした輝きや光など、興味深いディテールを加えてください。

#### ライティング

プロジェクトでライティングを導入する場合、どのように行うかを考えてください：

- ユーザーのための空間を機能的にライトアップします。
- リアルタイムライティングよりも効率的なベイクしたライティングを適宜使用します。
- ライティングの選択によって、ムードや求める美意識を表現することができます。

#### VFX

プロジェクトに VFX を導入する場合、どのようなことができるかを考えてみましょう：

- 天気やほこり、ホタルなどの環境効果を使って、シーンを生き生きとしたものにしましょう。
- ユーザーがアクションを完了すると煙が出るなど、ゲーム的な効果を利用して、特定のアクションに注目させます。
- 複数のパーティクルシステムを組み合わせることで、より複雑な効果を生み出すことができます。
- アプリケーションの動作が遅くなるような大規模なエフェクトには、VFX Graph を使用します。

#### アニメーション

プロジェクトにアニメーションを導入する場合、どのように行うかを考えてください：

- 重要なオブジェクトや興味深いオブジェクトにユーザーを引きつけるために、アニメーションを使用します。
- 複数のアニメーションを持つオブジェクトのアニメーターコントローラー (Animator Controller) を作成します。
- 必要に応じて、Unity Asset Store などのリソースから既存のアニメーションを使用します。

#### カメラ

プロジェクトにカメラを導入する場合、どのようにするかを考えてください：

- ユーザーが見るべきものすべてをはっきりと見ることができるようにしましょう。
- 一人称視点や三人称視点のカメラはプレイヤーの近くに設置し、プレイヤー自身に重点を置き、遠くのカメラは環境に重点を置くなど、ユーザーが主に注目すべき点を伝えます。
- カメラアングルやプレイヤーとの距離感で雰囲気を表現しましょう。

#### ポストプロセス

プロジェクトにポストプロセスを導入する場合、どのように行うかを考えてください：

- シーン全体のエフェクトにはグローバルボリュームを、特定のエリアのエフェクトにはローカルボリュームを使用します。
- Color Grading (カラーグレーディング) を使用して、特定のビジュアルスタイルを実現することができます。
- シーンの極端に明るい部分をよりよくシミュレートするには Bloom (*ブルーム*) を使用し、最高の状態で表示するには Tonemapping を使用します。
- アプリケーションにおけるポストプロセスの利点とパフォーマンスのコストのバランスをとることができます。

#### オーディオ

プロジェクトにオーディオを導入する場合、どのように導入するか考えてみましょう：

- アンビエントオーディオのソースを特定します。例えば、風が吹いている、鳥が鳴いているなど、シーンに必ずしも見えない音源であっても、聴覚的に表現してはいけないというわけではありません。
- 音源の距離を考慮し、適宜 Volume Rolloff で音量を調整してください。
- デザインコンセプトに合わせて、2D と 3D のオーディオソースを使い分けましょう。

#### UI

プロジェクトで UI を実装する場合、どのように行うのかを考えてください：

- さまざまなスクリーンサイズに対応できるよう、UI 要素のアンカー設定を行います。
- 基本的なアクセス性の要件を満たしていることを確認します。
- ユーザーが自分の体験をカスタマイズできるような UI を使用します（たとえば、設定メニューを使用）。
