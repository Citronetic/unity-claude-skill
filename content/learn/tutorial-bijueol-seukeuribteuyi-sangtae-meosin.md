[Image: 비주얼 스크립트의 상태 머신]Summary

상태 머신을 사용하면 프로젝트에 있는 오브젝트의 동작을 정교하게 제어할 수 있습니다. 그러면 다양한 상황에서 각각 서로 다른 이벤트에 반응하여 적절하게 적용될 수 있는 여러 상태(정지, 달리기, 싸우기, 부상 등)를 게임 오브젝트에 부여할 수 있습니다. 이 튜토리얼에서는 클라이브의 지하실 함정 문에 대한 상태 머신을 구축합니다.

이 튜토리얼에서 배울 내용은 다음과 같습니다.

- 상태 그래프와 스크립트 그래프를 구별합니다.
- 새 State Graph를 만듭니다.
- 상태 머신에서 상태에 대한 스크립트 그래프를 만듭니다.
- 상태 머신에서 다양한 스크립트를 살펴봅니다.
- 원하는 결과를 얻을 수 있도록 State Graph에서 전환을 계획하고 설정합니다.
- 기존의 복잡한 비주얼 스크립트를 해석합니다.
- 기존 스크립트 그래프를 상태 머신에서 사용할 수 있게 조정합니다.

## 1.  개요

Q&A (0)

비주얼 스크립팅에서 **상태**는 게임 오브젝트에 대해 정의하는 동작 또는 정보입니다. 애니메이터 컨트롤러와 함께 애니메이션 상태 머신을 사용해 본 경험이 있다면, 비주얼 스크립팅 상태 머신에 관한 개념이 낯설지 않을 것입니다. 상태를 일종의 교체 가능한 '특성'으로 간주할 수도 있는데, 게임 오브젝트는 상태에 따라 다른 행동을 나타내고, 이벤트 등 다양한 자극에 반응합니다.

예를 들면 문에는 열림, 잠김 또는 잠금 해제 등의 상태가, 게임의 플레이어 캐릭터에는 정지, 달리기, 전투, 부상 등의 상태가 적용될 수 있습니다. 각각의 경우에, 사용자가 버튼이나 키를 누르면 게임 오브젝트가 다른 작업을 수행하도록 하거나 특정 조건에서만 상태를 변경하고자 할 수 있습니다. 이벤트, 변수, 많은 If 유닛을 사용하여 이러한 상황을 프로그래밍하는 것도 가능하지만, 상태 머신은 훨씬 쉽고 더 효율적입니다.

이 튜토리얼에서는 함정 문의 세 가지 상태(Open, Closed, Filled)에 대한 상태 머신을 만들어 보겠습니다. 클라이브는 레버를 사용하여 Open 및 Closed 상태를 변경하고 상자를 문 아래 구멍에 밀어 Filled 상태로 만들 수 있습니다.

함정 문은 상태별로 서로 다른 이벤트 세트에 반응합니다. 예를 들어, 함정 문이 Open 상태이면 클라이브는 셀에 들어갈 수 없지만 상자는 구멍에 들어갈 수 있습니다. 그러나 함정 문이 Closed나 Filled 상태가 되면 클라이브와 다른 움직이는 오브젝트가 모두 정상적으로 통과할 수 있습니다. 그리고 클라이브는 Open 상태에서만 구멍을 채울 수 있습니다. 상태 머신은 이러한 다양한 동작 세트를 관리하는 데 적합합니다.

#### 상태 머신의 작동 방식

다음은 상태 머신의 구조를 숙지하는 데 도움이 되는 간략한 과정입니다.

**1.**계층 구조에서 **ObjectRoot > Trap Door**를 선택합니다.

**2.**인스펙터에 Script Machine과 State Machine이 표시됩니다. 앞서 TrapDoorLever를 테스트할 수 있도록 Script Machine을 제공했는데, 체크박스 선택을 취소하여 Script Machine을 비활성화하고 State Machine을 활성화하세요.

**3. Edit Graph** 버튼을 선택합니다. 이제 **State Graph**가 표시되고, 창 이름이 **State Graph**로 변경되었습니다. State Graph에는 유닛 대신 **상태**와 **전환**이 포함됩니다.

이 State Graph에는 **Open**이라는 이름의 스크립트 상태가 하나 포함되어 있습니다. 이 유닛의 텍스트는 내부의 이벤트를 나타냅니다.

[Image: image]

**4.**Open 상태를 더블 클릭하여 스크립트 그래프를 엽니다. 지금까지 만들어 온 것과 같은 그래프가 표시됩니다. 함정 문의 애니메이션화 플로를 시작하는 On Enter State 유닛과 Cancel Movement로 이어지는 Want To Enter Cell 유닛을 볼 수 있습니다. 나중에 이 스크립트를 완성할 것입니다.

[Image: image]

**5.**Script Graph 창의 메뉴 표시줄 왼쪽 상단, **Zoom** 왼쪽에서 **TrapDoor**를 선택하여 상태 그래프로 돌아갑니다.

**6.**상태 그래프의 그래프 창을 오른쪽 클릭하고 **Create Script State**를 선택합니다. 그러면 새 Script State가 나타납니다.

[Image: image]

**1.**Graph Inspector에서 이 Script State의 **Title**을 **Closed**로 변경합니다.

**2.**Closed 상태를 더블 클릭하여 Script Graph를 엽니다. 기본적으로 3개의 이벤트가 포함되어 있는데, **Update**와 **On Exit State**를 삭제합니다. 이후 돌아와 On Enter State를 편집할 것입니다.

**3.**Script Graph 창의 메뉴 표시줄 왼쪽 상단에서 **TrapDoor**를 선택하여 다시 상태 그래프로 돌아갑니다.

**4.**Closed 상태를 오른쪽 클릭하고 **Duplicate**를 선택합니다.

**5.**Graph Inspector에서 이 Script State의 **Title**을 **Filled**로 변경합니다.

State Graph는 아래 이미지와 같아야 합니다.

[Image: image]

상태에 포함된 스크립트 그래프를 편집하여 상태별 동작을 정의해 보겠습니다.

## 2. Open 상태 스크립트 작성

Q&A (0)

Open 상태는 이 상태 그래프에서 가장 복잡합니다. 먼저 익숙한 두 개의 기존 플로를 편집하는 것부터 시작하겠습니다.

#### On Enter State

On Enter State는 이 상태가 입력될 때마다 한 번 실행됩니다. 상태가 Open으로 변경되면 함정 문이 열립니다.

AnimAndFX 슈퍼 유닛을 사용하여 함정 문이 열리게 만들어 보세요. TrapDoor 게임 오브젝트 애니메이션의 경우, 파라미터 이름은 Switched이고 True를 입력하면 문을 여는 애니메이션이 플레이됩니다.

#### Want To Enter Cell

기존의 플로는 열 방법이 없는 잠긴 문일 뿐입니다. 대신 이 플로에서는 함정 문이 열려 있다면 클라이브가 들어가는 것을 막는 동시에 구멍으로 빠질 수 있는 상자나 기타 오브젝트는 허용해야 합니다.

그러면 빠질 수 있는 오브젝트와 빠질 수 없는 오브젝트를 어떻게 구분할 수 있을까요? CanFall이라는 Object 변수를 사용하여 이를 처리할 수 있는데, 이 변수는 빠질 수 있는 오브젝트에만 생성됩니다. 그런 다음 부울 값을 출력하는 **Has Variable** 유닛을 사용하여 이 변수의 존재를 확인할 수 있습니다. 모든 게임 오브젝트에 부울 값 CanFall 변수를 추가하는 것보다 훨씬 쉽죠.

이 플로에서 CanFall 변수가 없는 경우(Has Variable이 False를 출력) Cancel Movement를 통해 이동을 취소하도록 스크립팅합니다. 이렇게 하면 클라이브가 구멍에 빠지는 것을 막을 수 있습니다.

CanFall 변수가 있다면 어떻게 처리하고, 구멍에 빠지는 오브젝트의 스트립트는 어떻게 작성할까요? 게임의 첫 번째 레벨에서 이 효과를 확인했습니다. 이미 했던 작업을 반복하는 대신, 첫 번째 게임 레벨에서 비주얼 스크립트를 빌려 오겠습니다.

## 3. 샘플 씬 활용

Q&A (0)

게임의 첫 번째 레벨에서, 클라이브는 열쇠를 얻기 위해 상자를 구멍에 밀어 넣어야 합니다. 그 비주얼 스크립트를 찾아서 활용해 보겠습니다.

**2.**프로젝트 창에서 **Assets > VisualScriptingTutorial > CompleteGame > Scenes > SampleScene**으로 이동하여 씬을 엽니다.

**3.**씬 뷰에서 클라이브가 열쇠에 도달하기 위해 채우는 구멍을 선택합니다. 계층 구조에서 이 구멍은 Pit라는 이름으로, ObjectRoot의 자식임을 확인할 수 있습니다.

[Image: image]

**4.**인스펙터 창에서 Script Machine 컴포넌트를 찾아 **Edit Graph** 버튼을 선택합니다.

#### 스크립트 해석

복잡한 비주얼 스크립트이지만 충분히 이해할 수 있습니다. 아래 요약을 읽기 전에 비주얼 스크립트를 읽어 보세요.

요약:

- Want To Enter Cell 플로에서 CanFall이 발견되면, FallingMovingObject라는 이름의 Graph 변수가 셀에 들어가려는 Moving Object의 사본에 설정됩니다.
- Update 플로에서 모든 프레임마다 수행하는 작업은 다음과 같습니다.

- FallingMovingObject가 Null인지 확인합니다.
- Null인 경우, 이 프레임에서 아무것도 발생하지 않습니다.
- Null이 아닌 경우, 구멍에 빠지는 게임 오브젝트의 복사본을 가져옵니다.
- 구멍 바닥을 향해 FallingMovingObject를 매우 짧은 거리로 옮깁니다.
- 구멍 바닥과 오브젝트 사이의 거리가 사실상 0(0.001 이하)이면, FallingMovingObject를 다시 Null로 설정하여 이 플로가 다음 프레임에서 오브젝트를 계속 움직이지 못하도록 합니다.

이러한 정보를 고려하여 이 로직을 따르고 이 Update 플로가 Open 상태에서 작동하게 할 수 있는지 확인하세요. 필요에 따라 다음 단계의 이미지를 참고하여 작업 현황을 확인할 수 있습니다. 작업을 반드시 저장하세요(**Ctrl + S/Cmd + S**).

아직은 테스트할 수 없으며, 먼저 상태 머신을 만들어야 합니다. 작업물을 점검하려면 Samples 하위 폴더에서 **Final_TrapDoorOpenState**를 참고하세요.

성공하면 다음 단계를 완료로 표시합니다. 막히게 되면 다음 단계의 지침을 따라 하면 됩니다.

## 4.  빌려 온 Update 플로 적용(지침)

Q&A (0)

이 Update 플로를 사용하도록 준비하는 방법은 다음과 같습니다.

**1.**SampleScene의 비주얼 스크립트에서 Update 플로의 모든 유닛을 복사하고 Open 상태의 스크립트 그래프에 있는 빈 영역에 붙여 넣습니다.

**2.**TrapDoor의 Blackboard 창에서 FallingMovingObject라는 이름의 Graph 변수를 만들고 Type은 Null로 둡니다.

**3.**Want To Enter Cell 플로에서 CanFall이 존재하는 경우, FallingMovingObject 변수를 이벤트에 서 출력되는 Moving Object로 설정합니다. 이렇게 하면 Update 플로를 활성화할 수 있습니다.

이 Update 플로를 Open 상태에 적용해 보겠습니다.

**4.**Update 플로의 최종 유닛은 Passable이라는 이름의 변수를 True로 설정하는 유닛이지만, 상태 머신이 이를 처리하기 때문에 함정 문이 통과 가능한지 여부를 추적할 필요가 없습니다. 이 유닛을 삭제합니다.

**5.**Update 플로의 끝 지점에 Custom Event Trigger 유닛을 추가하고 이벤트 이름을 HoleFilled로 설정합니다. 나중에 이 이벤트에 대한 스크립트를 작성해 보겠습니다.

**6.**그룹과 코멘트로 이 플로를 어떻게 개선할 수 있을까요? 필요한 만큼 그룹과 코멘트를 추가하여 이 스크립트에서 어떤 일이 발생하는지 추적하세요.

**7.**작업을 저장합니다.

이 스크립트는 이미지로 표시하기에 너무 크므로, 작업물이 올바른지 확인하려면 Samples 하위 폴더에서 **Final_TrapDoorOpenState**를 참조하세요.

이제 Open 상태가 준비되었습니다. 상태가 입력되면 애니메이션을 플레이하고, 구멍에 빠지도록 지정된 오브젝트에만 진입을 허용할 수 있으며(CanFall 변수 사용), 빠지는 오브젝트를 Update 이벤트를 사용하여 프레임 단위로 구멍까지 옮길 수 있습니다. 이러한 과정은 나중에 테스트할 예정입니다.

## 7. 전환 스크립트 작성

Q&A (0)

세 가지 상태에 대한 스크립트 그래프가 준비되었지만, 이 상태 머신의 로직 일부가 여전히 누락된 상태입니다. TrapDoor 게임 오브젝트는 어떤 조건에서 다른 상태로 변경될까요? 이어서 상태 그래프에 **전환**을 추가하여 이러한 조건을 설정할 수 있습니다.

전환을 사용하면 상태를 다른 모든 상태로 변경할 수 있는 조건을 지정할 수 있습니다. 다음은 이 상태 머신의 전환에 대한 규칙입니다.

[Image: image]

참고로 구멍이 채워지면 상태를 변경할 방법이 없습니다. 그리고 제한된 수의 전환만 가능합니다. 상태 머신은 게임이 플레이되는 동안 가능한 상황을 지정하기 위한 논리적 구조를 제공합니다.

위의 표에 따라 이 상태 머신에 전환을 추가해 보겠습니다.

**1.**TrapDoor 오브젝트의 상태 그래프를 엽니다.

**2.**Open 상태에서 Closed 상태로 전환하도록 하려면 Open 상태를 오른쪽 클릭하고 **Make Transition**을 선택한 다음 Closed 상태를 클릭합니다. 그러면 상태 그래프가 아래 이미지처럼 표시됩니다.

[Image: image]

**3.**두 상태 사이의 전환을 더블 클릭하여 이 전환에 대한 스크립트 그래프를 엽니다. 스크립트에는 **State: Trigger Transition**라는 유닛이 기본적으로 포함되며, 전환이 발생하려면 스크립트를 이 유닛으로 종료해야 합니다.

**4.**이 전환을 일으키는 이벤트의 이름은 LeverSwitched입니다. LeverSwitched는 레버를 켜거나 끌 때 트리거되는 이벤트로, 부울 값을 전달합니다. Custom Event 유닛을 추가하고  LeverSwitched라는 이름을 입력한 다음 Arguments 값을 1로 설정합니다. 이는 TrapDoorLeverScript의 Custom Event Trigger 유닛과 일치합니다.

**5.**If 유닛을 추가하고 Custom Event 유닛의 플로와 값 커넥터를 모두 연결합니다.

**6.**If 유닛의 True 브랜치를 State: Trigger Transition 유닛에 연결합니다.

[Image: image]

**7.**상태 그래프로 돌아갑니다.

**8.**Closed 상태에서 Open 상태로의 전환을 만들려면, Closed 상태에서 Open 상태로의 전환을 만드는 것을 제외하고 위의 단계를 반복합니다. 그리고 LeverSwitched 이벤트의 값이 True인 경우 전환이 발생하도록 허용합니다.

[Image: image]

**9.**상태 그래프로 돌아갑니다.

**10.**Open 상태에서 Filled 상태로의 전환을 만듭니다. 해당 스크립트에서 HoleFilled 이벤트가 트리거될 때 전환을 수행하도록 지정하기만 하면 됩니다.

[Image: image]

**11.**작업을 저장합니다.
