## 1. 개요

Q&A (0)

혼자 작업하든 팀으로 작업하든 관계없이 프로젝트를 개발하는 데 중요한 한 가지 측면은 프로젝트 파일 관리 방법을 결정하는 일입니다. 1인 개발자의 경우 유일한 프로젝트 인스턴스를 로컬 하드 드라이브에 보관하는 일과 관련된 위험이 항상 도사리고 있습니다. 예를 들어 드라이브에 오류가 발생하면 프로젝트가 손실됩니다. 여러 프로젝트 백업 복사본을 다른 드라이브에 보관하거나 클라우드에 저장하면 최신 상태로 유지하기가 번거로울 수 있습니다. 팀에 속한 개발자의 경우 모든 사람이 프로젝트에 액세스하는 방법과 더불어 한 사람이 수행 중인 작업이 다른 사람의 작업을 덮어쓰거나 손상시키지 않도록 하는 방법을 파악해야 합니다.

다행히도 이러한 모든 문제에 대한 솔루션은 꽤나 간단합니다. 바로 **버전 관리**입니다.

버전 관리가 복잡해 보이더라도 걱정하지 마세요. 많은 사람들이 처음 개발을 시작할 때 버전 관리에 대해 부담감을 느낍니다. 초보 개발자의 경우 첫 번째 저장소를 설정할 때 잘못된 시작과 혼란을 겪으며 다시 시도하기를 주저하게 될 수 있으며, 이때 버전 관리의 유용성을 간과할 수 있습니다. 이러한 유형에 해당한다면 혼자가 아니라는 사실을 명심하고 이 프로젝트에서 다시 시도해 보세요.

## 2. 버전 관리란?

Q&A (0)

**버전 관리**(소스 관리라고도 함)는 정보를 관리하고 추적하는 시스템입니다. 버전 관리 시스템은 모든 종류의 파일이나 소프트웨어, 웹사이트, 기타 데이터에 대한 변경 사항을 저장, 관리, 추적하도록 설정할 수 있습니다.

개인이나 소규모 팀, 대규모 조직은 복잡한 프로젝트를 간편하게 백업하고 관리하기 위해 버전 관리 시스템을 사용하기도 합니다. 버전 관리 시스템은 클라우드 스토리지 서비스와 함께 작동하므로 다음과 같은 유용한 기능을 활용할 수 있습니다.

- 백업 스토리지
- 수정 사항 추적
- 프로젝트 관리

이 튜토리얼에서는 로컬 스토리지를 사용하는 버전 관리 시스템과 달리 클라우드 스토리지를 사용하는 버전 관리 시스템을 알아보겠습니다. 후자가 팀의 특수한 상황에 더 적합합니다.

## 3. 누가 버전 관리를 사용하나요?

Q&A (0)

조직화된 프로젝트 또는 소프트웨어 개발에 여러 팀원이 참여하는 경우 버전 관리 시스템이 없으면 관리 작업이 어려워질 수 있습니다. 버전 관리는 모두에게 필요합니다.

프로젝트가 점점 더 복잡해짐에 따라 팀원들은 동료 팀원이 최근에 변경한 사항을 파악하고 있어야 합니다. 일관되게 조율하지 않으면 비효율성, 병목 현상, 코드 손실, 재작업 등 많은 고충에 직면하게 됩니다. 버전 관리의 목적은 이러한 문제를 방지하는 것입니다.

## 4. 버전 관리 툴 선택

Q&A (0)

버전 관리 시스템은 프로젝트 요구 사항에 따라 달라집니다. Unity에는 **Collaborate**라는 버전 관리 솔루션이 있으며, 패키지로 제공됩니다. 그러나 이 학습 프로젝트에서는 매우 널리 사용되는 버전 관리 솔루션 **Github**를 사용합니다. 개발 경력을 쌓다 보면 GitHub를 접하기 쉽습니다. 이 솔루션은 특히 버전 관리를 처음 사용하는 경우에도 간단하게 사용할 수 있습니다.

손쉬운 작업을 위해 사용이 간편한  **GitHub Desktop**을 사용하는 방법을 소개하겠습니다. 이 솔루션을 사용하면 Git 커맨드를 사용하는 커맨드 라인 대신 GUI(그래픽 사용자 인터페이스)를 통해 GitHub 프로젝트에 액세스할 수 있습니다. 이미 GitHub를 능숙하게 사용하고 있거나 커맨드 라인 사용을 선호한다면 다음 단계를 건너뛰어도 무방합니다.

Unity가 다른 버전 관리 시스템과 통합되는 방식을 자세히 알아보려면 [Unity Collaborate 소개](https://learn.unity.com/tutorial/introduction-to-unity-collaborate?uv=2020.1&pathwayId=5f7e17e1edbc2a5ec21a20af&missionId=5f779f1eedbc2a00201f3e5e&projectId=5fadaa43edbc2a0020bdedfd)와 [Unity 및 Helix Core Perforce 사용](https://learn.unity.com/tutorial/working-with-unity-and-helix-core-perforce?uv=2020.1&pathwayId=5f7e17e1edbc2a5ec21a20af&missionId=5f779f1eedbc2a00201f3e5e&projectId=5fadaa43edbc2a0020bdedfd)에 관한 튜토리얼을 참조하시기 바랍니다.

## 5. GitHub Desktop 시작

Q&A (0)

GitHub 저장소를 만들려면 무료 GitHub 계정을 생성한 후 GitHub Desktop을 설치해야 합니다.

설정 방법은 다음과 같습니다.

**1.**  아직 계정이 없다면 [github.com](https://github.com/)에서 무료 GitHub 계정을 생성합니다.

**2.**  Mac과 PC 모두에서 사용할 수 있는 GitHub Desktop을 [desktop.github.com](https://desktop.github.com/)에서 다운로드하여 설치합니다. 사용 중인 플랫폼을 사이트가 자동으로 감지하지만, 사용자가 직접 플랫폼 유형을 선택할 수도 있습니다.

**3.**  설치 후 다음과 같이 GitHub Desktop에서 계정에 로그인합니다.

- Windows의 경우 **File** > **Options**> **Account**를 선택합니다.
- Mac의 경우 **GitHub Desktop** > **Preferences**를 선택합니다.

계정 로그인 및 인증에 관한 자세한 내용은 [GitHub 문서](https://docs.github.com/en/desktop/installing-and-configuring-github-desktop/authenticating-to-github)에서 확인할 수 있습니다.

아직 계정과 연결된 저장소가 없는 경우 시작하도록 권장하는 다음과 같은 시작 화면이 표시됩니다.

## 6. 하드 드라이브에 새 저장소 만들기

Q&A (0)

GitHub 저장소(repo)는 프로젝트가 있는 폴더입니다. 이 폴더 내에서 버전 관리 소프트웨어가 모든 변경 사항을 주의 깊게 추적합니다. 가장 먼저 Unity 프로젝트용으로 특별히 설정된 빈 저장소를 만들어야 합니다.

**1.**GitHub Desktop 시작 화면에서 **Create a New Repository on your Hard Drive**를 선택합니다.

[Image: image]

GitHub Desktop의 상단 메뉴에서 **File**>**New Repository**를 클릭해도 됩니다.

**2.**표시되는 **Create a New Repository** 창에서 다음과 같이 저장소의 설정을 구성합니다.

- **Name** 필드에 저장소 이름을 입력합니다(예: 'Jr-Programmer-Project'). 공백은 하이픈으로 대체됩니다.
- **Local Path** 필드에서 저장소를 저장할 경로를 선택합니다. 방금 입력한 이름의 폴더가 이 경로에 생성됩니다.

**Git Ignore** 드롭다운에서 **Unity** 옵션을 선택합니다. 이렇게 하면 버전 관리에 저장하고 싶지 않은 모든 파일 유형을 나열하는, 사전 구성된 .gitignore 파일이 저장소에 생성됩니다. Unity의 경우 프로젝트 관련 파일에만 집중하고 다른 모든 것은 무시합니다.

[Image: image]

**3.  Create Repository**를 선택합니다. 그러면 새 저장소에 **Current Repository** 드롭다운이 설정됩니다. 메인 창에 'No local changes'가 표시됨을 확인할 수 있습니다. 아직 편집하지 않은 새로운 저장소이기 때문에 이 메시지가 표시됩니다.

[Image: image]

**4.**컴퓨터의 지정된 위치에 방금 생성된 폴더를 엽니다. 컴퓨터가 숨겨진 파일을 표시하도록 설정된 경우 다음 세 가지 항목이 폴더에 표시됩니다.

- .git folder
- .gitattributes
- .gitignore

[Image: image]

.git 폴더를 통해 GitHub에서는 이 저장소가 실제로 GitHub 저장소임을 알 수 있습니다. .gitignore 및 .gitattributes는 저장소의 구성을 지정합니다. 필수는 아니지만, 이러한 숨겨진 파일을 확인하고 싶다면 Windows 또는 Mac에서 숨겨진 파일을 확인하는 방법을 Google에서 검색해 보세요.

다음 단계에서는 GitHub에 추적할 항목을 제공하기 위해 실제 Unity 프로젝트를 이 폴더에 넣어 보겠습니다.

## 8. 최초 커밋 수행 및 저장소 퍼블리시

Q&A (0)

저장소에 커밋하는 첫 번째 파일 세트는 **최초 커밋**에 해당합니다. 프로젝트를 처음 설정한 후에 처음으로 커밋하는 것이 보통이므로, 지금 바로 커밋을 수행해 보겠습니다.

**1**.  저장소 관련 변경 사항이 나열된 섹션 아래의 **Summary** 필드에 'initial commit'을 입력한 다음 **Description** 필드에 설명(예: 'project starter files')을 입력합니다. 그런 다음 **Commit to main**을 선택하여 프로젝트의 기본 브랜치에 변경 사항을 저장합니다. 브랜치가 무엇인지 몰라도 걱정하지 마세요. 튜토리얼 후반부에서 다룰 예정입니다.

[Image: image]

**Commit**을 클릭하면 모든 변경 사항이 버전 관리에 안전하게 저장되므로 목록에 표시된 모든 변경 사항이 사라집니다.

그러나 모든 변경 사항이 하드 드라이브에서 로컬로 추적되지만, 실수로 컴퓨터를 절벽에서 떨어뜨리면 어떻게 될까요? 모든 작업이 손실될 것입니다. 만일을 대비하여 프로젝트를 클라우드에 백업하겠습니다.

**2**.  GitHub Desktop 인터페이스에서 **Publish Repository**를 선택합니다.

[Image: image]

**3.**열리는 창에서 프로젝트 이름과 더불어 코드의 공개 여부를 확인합니다. 그런 다음 **Publish Repository**를 선택합니다.

[Image: image]

**4.**GitHub.com에 백업 및 퍼블리시된 저장소를 보려면 GitHub Desktop의 상단 메뉴로 이동하여 **Repository**>**View on GitHub**를 선택합니다. 여기에서 모든 파일을 탐색하고, 커밋 이력을 확인하고, 문제를 로깅하는 등의 다양한 작업을 수행할 수 있습니다. 익숙해질 수 있도록 인터페이스를 자유롭게 살펴보세요.

## 9. 버전 관리의 작동 방식

Q&A (0)

**변경 사항 푸시 및 풀**

버전 관리 사용 시 적용한 변경 사항을 문서화하는 메모와 함께 클라우드 저장소(또는 파일 스토리지 디렉토리)를 통해 프로젝트에 대한 변경 사항을 저장합니다.

이를 통해 최신 프로젝트 버전을 **풀**(다운로드)하여 열고 로컬에서 변경한 후 변경 사항을 클라우드 저장소로 다시 **푸시**(업로드)할 수 있습니다.

**변경 사항 병합**

여러 사람이 동시에 동일한 프로젝트를 함께 작업할 때 똑같은 파일을 다르게 변경하는 경우도 있습니다. 예를 들어 한 사람은 Unity 프로젝트의 프랍(prop) 에셋에 할당된 텍스처를 변경하고 다른 사람은 씬에서 위치를 변경할 수도 있습니다. 버전 관리는 **병합**이라고 하는 프로세스를 통해 프로젝트 파일을 관리하여 모든 변경 사항을 조합하고 통합합니다. 경우에 따라 프로젝트 파일에 적용된 변경 사항이 동일한 값에 영향을 줄 수 있습니다. 이 경우, 버전 관리 시스템이 변경 사항을 함께 병합할 수 없어 **병합 충돌**이 일어나기 때문에 개발자가 개입해야 합니다. 버전 관리 시스템은 일반적으로 서로 다른 두 값을 나란히 표시하여 충돌을 식별합니다. 그러면 개발자가 충돌을 해결하기 위해 유지할 항목을 결정합니다.

**이전 버전으로 되돌리기**

버전 관리의 주요 이점 중 하나는 시간 경과에 따른 모든 변경 사항을 수시로 확인할 수 있다는 점입니다. 변경 사항이 충돌하는 경우 또는 이전 버전으로 되돌리는 것이 최선이라고 판단되는 경우에는 언제든지 프로젝트의 이전 버전으로 돌아가 프로젝트를 복원할 수 있습니다.
