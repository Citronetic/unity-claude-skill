스크립팅의 핵심은 로직으로, 논리적인 시퀀스를 고안하여 스크립트로 코딩하는 작업입니다. 이 튜토리얼에서는 게임의 필수 스크립트 오브젝트인 '문'에 대한 설명으로 시작할 것이며, 문을 열고 닫는 논리적 시퀀스를 구체적으로 안내합니다.

이 튜토리얼의 주요 목표는 이러한 로직 시퀀스를 작업자가 직접 코딩할 수 있도록 돕는 것입니다. 제공된 단계별 지침은 그대로 따라도 되고 생략해도 됩니다.

이 튜토리얼에서 배울 내용은 다음과 같습니다.

- Script Machine의 비주얼 스크립트를 교체합니다.
- Boolean 값을 적용하고 비주얼 스크립트에 브랜칭합니다.
- 비주얼 스크립트에서 변수 값을 불러오고 설정합니다.
- 기존 이벤트를 비주얼 스크립트에 적용합니다.
- 슈퍼 유닛을 비주얼 스크립트에 적용합니다.
- 원하는 결과가 주어지면 적절한 비주얼 스크립트를 코딩합니다.

## 2. 이 게임의 스크립팅된 이벤트

Q&A (0)

이 프로토타입에는 C#으로 스크립팅된 여러 이벤트가 포함되어 있는데, 게임에서 움직이는 오브젝트를 확인하고 제어하는 데 이러한 이벤트를 사용하게 됩니다. 이벤트를 모두 기억해야 할 필요는 없지만, 이벤트 이름으로 작동 방식을 파악할 수 있다면 이 튜토리얼 전반에서 이벤트를 사용하는 방법을 이해할 수 있을 것입니다.

#### 셀에 있는 게임 오브젝트의 이벤트

이 게임은 1x1 셀의 그리드로 구성됩니다. 그리드의 각 셀은 고양이 클라이브나 상자처럼 움직이는 게임 오브젝트가 셀 안팎으로 이동할 때 이벤트를 트리거할 수 있습니다.

- **Want To Enter Cell**은 움직이는 게임 오브젝트가 셀로 들어가려고 할 때 트리거됩니다. 그러한 오브젝트가 셀로 들어갈 수 있는지 여부를 결정하는 스크립트에서 이 이벤트를 사용할 수 있습니다.
- **Enter Cell**은 움직이는 게임 오브젝트가 셀로 들어갈 때 트리거됩니다. 이 이벤트를 사용하면 다음에 일어날 일을 결정할 수 있습니다.
- **Want To Exit Cell**은 움직이는 게임 오브젝트가 셀에서 나가려고 할 때 트리거됩니다. 이 이벤트를 사용하면 오브젝트가 나가는 것을 허용할지 여부를 결정할 수 있습니다.
- **Exit Cell**은 움직이는 게임 오브젝트가 셀을 나갈 때 트리거됩니다. 이 이벤트를 사용하면 다음에 일어날 일을 결정할 수 있습니다.

#### 모서리에 있는 게임 오브젝트의 이벤트

문과 같은 오브젝트는 다음의 이벤트를 트리거할 수 있습니다.

- **Want To Cross Edge**는 움직이는 게임 오브젝트가 모서리를 통과하거나 넘어갈 때 트리거됩니다. 이 이벤트를 사용하면 오브젝트가 지나가는 것을 허용할지 여부를 결정할 수 있습니다.
- **Crossing Edge**는 움직이는 게임 오브젝트가 모서리를 지나갈 때 트리거됩니다. 이 이벤트를 사용하면 다음에 일어날 일을 결정할 수 있습니다.

## 3.  닫힌 문에 대한 스크립트 점검

Q&A (0)

첫 번째 문을 제어하는 비주얼 스크립트를 살펴보고 어떤 일이 발생하는지 알아보겠습니다.

**1. ObjectRoot**> **FirstDoor**를 선택합니다.

**2.**인스펙터에서 AnimAndFX 스크립트가 있는 Script Machine 컴포넌트를 제거하겠습니다. 이 스크립트로 해 볼 테스트는 모두 마쳤기 때문입니다. 컴포넌트 섹션에서 세 개의 점으로 표시된 아이콘을 누르고 **Remove Component**를 선택합니다.

**3.**남아 있는 Script Machine 컴포넌트에는 **BaseDoorScript** 비주얼 스크립트가 연결되어 있습니다. 이 스크립트는 여러 문에 연결되어 있으므로 편집하지 마세요. 대신 프로젝트 창에서 BaseDoorScript를 선택하고 Ctrl+D/Cmd+D를 눌러 복제합니다.

**4.**복제한 스크립트의 이름을 **FirstDoorScript**로 변경합니다.

**5.**FirstDoorScript를 Script Machine의 **Graph** 프로퍼티로 드래그해 BaseDoorScript와 교체합니다.

**6. Edit Graph** 버튼을 선택합니다.

**7.**Script Graph 창 상단의 메뉴에서 Values 버튼을 활성화합니다.

Script Graph 창은 아래 이미지와 같아야 합니다.

[Image: image]

**8.**Script Graph 창이 열린 상태에서 이 레벨을 플레이합니다. 클라이브가 시작하는 방의 오른쪽에 있는 문을 통해 클라이브를 움직여 보세요. 클라이브는 문을 통과할 수 없으며, 통과하려 할 때마다 이 스크립트가 실행됩니다.

**9.**그래프에서 어떤 일이 일어나는지 보려면 Want To Cross Edge 유닛을 선택하고 Graph Inspector를 확인하세요. 이 유닛의 출력은 **Moving Object**라고 하는 오브젝트로, C# 코드에 사용자가 이 모서리를 건너 이동시키려는 게임 오브젝트로서 정의되어 있습니다.

**10.**Cancel Movement 유닛을 선택합니다. 이 유닛은 입력 Moving Object에 대해 작용하여 움직임을 멈추게 하는 C# 유닛(코딩 작업자를 위한 메서드)입니다.

따라서 클라이브가 이 경계를 넘으려 하면 움직임이 취소됩니다. 이 문은 잠겨 있습니다.

## 4. 클라이브가 문을 통과하도록 하기

Q&A (0)

변수를 사용하여 이 문을 잠금 해제해 보겠습니다. IsOpen이라는 Object 변수를 사용하여 문이 열려 있는지 여부를 지정하고, 인스펙터에서 값을 제어해 보겠습니다. 스크립트는 다음과 같이 작동하게 됩니다.

클라이브가 문을 통과하려고 할 때:

- 문이 열려 있으면 클라이브가 그대로 이동하도록 합니다(아무것도 하지 않음).
- 문이 닫혀 있으면 클라이브의 이동을 취소합니다.

이제 이 플로를 직접 만들어 보세요. 필요에 따라 다음 단계의 이미지를 참고하여 작업 현황을 확인할 수 있습니다. 작업을 반드시 저장하세요(**Ctrl + S**/**Cmd + S**).

그런 다음, 플레이 모드를 실행하여 비주얼 스크립트를 테스트합니다. 인스펙터의 Object 변수 설정을 사용하여 IsOpen 변수의 값을 변경하고, 게임(Game) 뷰 창을 선택하여 초점을 게임으로 되돌립니다.

IsOpen이 True이면 클라이브가 철문을 바로 통과합니다. 이상적인 상황은 아니지만 우선 이렇게 시작하는 거죠.

## 5. 클라이브가 문을 통과하도록 하기(지침)

Q&A (0)

다음은 클라이브가 첫 번째 문을 통과할 수 있도록 하는 단계별 지침입니다.

**1.**IsOpen이라는 Object 변수를 만들고 Type은 Boolean으로, Value는 False(체크박스 선택 해제)로 지정합니다.

**2.**IsOpen 변수를 블랙보드의 Object 탭에서 스크립트로 드래그하여 Get Variable 유닛을 만듭니다.

**3.**IsOpen이 True인지 확인하기 위해 If 유닛을 추가하고, Get Variable에서 If 유닛의 입력부로 커넥터를 추가합니다.

**4.**Want To Cross Edge 유닛에서 Cancel Movement 유닛으로 연결되는 플로 커넥터(화살표)를 제거하고, 대신 Want To Cross Edge에서 If 유닛으로 연결합니다.

**5.**Want To Cross Edge 유닛에서 Cancel Movement 유닛으로 이어지는 Moving Object 데이터 출력 커넥터(점)를 유지합니다. 이 부분은 Cancel Movement에게 어떤 게임 오브젝트의 이동을 취소할지 전달하는 역할을 합니다.

**6.**If 유닛의 False 플로 출력부에서 Cancel Movement 유닛으로 플로를 연결합니다.

**7.**If 유닛의 True 출력부에서 플로를 연결하지 않습니다. 이 경우에는 아무 일도 발생하지 않아 이동이 취소되지 않기 때문입니다.

**8.** 작업을 저장합니다(**Ctrl + S/Cmd + S**).

## 6.  클라이브가 문을 열도록 하기

Q&A (0)

작업자가 제어하는 것이 아니라 클라이브가 직접 문을 열도록 이 그래프를 변경해 보겠습니다. 처음 이동을 시도하면 전진은 불가하지만 문은 열리고, 다음 번에 시도할 때에는 문이 열린 상태여서 이동이 취소되지 않을 것입니다. 스크립트는 다음과 같이 작동하게 됩니다.

클라이브가 문을 통과하려고 할 때:

- 문이 열려 있으면 클라이브가 그대로 이동하도록 합니다(아무것도 하지 않음).
- 문이 닫혀 있으면 클라이브의 이동을 취소하고 문이 열리도록 설정합니다. 문 자체는 바뀌지 않지만 클라이브가 문을 통과할 수 있습니다.

그래프를 수정하고 스크립트를 업데이트하세요. 필요에 따라 다음 단계의 이미지를 참고하여 작업 현황을 확인할 수 있습니다. 작업을 반드시 저장하세요(**Ctrl + S/Cmd + S**).

테스트할 때 처음으로 클라이브를 움직이려고 하면 문 앞에서 정지하지만, IsOpen 변수 값이 True로 변경됩니다. 다시 시도하면 클라이브가 문을 통과해야 합니다.
