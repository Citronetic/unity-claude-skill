## 2. ポータルのウィンドウとコンテンツのためのレイヤーを追加する

Q&A (0)

見えるものと見えないものを制御するには、Unity のレイヤーシステムを使用します。**レイヤー**が提供する簡単な方法を使用して、ゲームオブジェクトを異なるグループに分けることができます。その後、配置されているレイヤーに基づいて、ゲームオブジェクトのグループごとに個別に動作を制御できます。

ポータルアプリケーションの場合は、ポータルウィンドウ用に 1 つのレイヤーを作成し、ポータルのコンテンツ（ポータルの内部にあるすべてのもの）のために別のレイヤーを作成します。

以下の手順のようにして、2 つの新しいレイヤーを作成します。

**1.**ツールバーから「**Layers**」ドロップダウンダウンを選択して、「**Edit Layers**」を選択します。

[Image: image]

**2.**「**Layers**」折りたたみ項目を展開します。

**3.**  「**User Layer 6**」には「PortalWindow」と入力し、「**User Layer 7**」には「PortalContents」と入力します。レイヤー 3 を使用することもできますが、これらのレイヤーはレイヤー 6 と 7 のように隣同士にしておく方が簡単です。

**ノート**：「PortalContents」を「PortalWindow」より高いレイヤー番号に入力することが重要です。後で、レイヤー番号が高い方の内容を、アプリケーションでレンダリングするものから除外します。

## 3. ゲームオブジェクトを適切なレイヤーに配置する

Q&A (0)

必要なレイヤーを作成しましたが、ゲームオブジェクトをこれらのレイヤーにまだ配置していません。次の手順に従って、ポータルウィンドウとポータルのコンテンツを適切なレイヤーに割り当てます。

**1.**Project ウィンドウで**ポータル**のプレハブをダブルクリックし、シーンビューでそれを開きます。

**2.**「Hierarchy」で、「**Window**」ゲームオブジェクトを展開して、「**Glass**」ゲームオブジェクトを選択します。

**3.**Inspector の上部で、「**Layer**」ドロップダウンから「**PortalWindow**」を選択します。

[Image: image]

**4.**「Hierarchy」で、ポータル世界内のすべてのゲームオブジェクトを含む「**[テーマ]_Level**」親ゲームオブジェクトを選択します。

**5.**「**Layer**」ドロップダウンで「**PortalContents**」を選択します。

**6.**  「Change Layer」ダイアログウィンドウが表示されたら、「**Yes, change children**」を選択します。レベルのすべての子ゲームオブジェクトを、このレイヤーに含める必要があります。

[Image: image]

**7.**  「Hierarchy」でゲームオブジェクトを調べて、ポータルの「**Glass**」ゲームオブジェクトが「PortalWindow」レイヤーにあること、および他のすべてのゲームオブジェクトが「PortalContents」レイヤーにあることを確認します。

## 4. カスタムシェーダーをポータルウィンドウに適用する

Q&A (0)

[シェーダー](https://docs.unity3d.com/Manual/shader-introduction.html)は、画面にマテリアルを表示する方法を決定する計算を実行します。適用するシェーダーの種類により、同じマテリアルでも非常に異なる表示になる場合があります。

例えば、同じレンガのマテリアルに 3 つの異なるシェーダーを適用した次の例を見てください。

[Image: image]

ポータルウィンドウに 1 つのレイヤーのオブジェクトだけが表示され、他のレイヤーは表示されないようにするには、カスタムシェーダーを使用する必要があります。このシェーダーは通常のシェーダーと同じように動作しますが、1 つの重要な違いとして、「**ZWrite**」プロパティが無効にされています。この概念はこのチュートリアルには少し複雑すぎますが、ZWrite プロパティの詳細については[ドキュメント](https://docs.unity3d.com/Manual/SL-ZWrite.html)を読むとわかります。

以下の手順に従って、カスタムシェーダーをポータルウィンドウに適用します。

**1.**ポータルのプレハブを「Hierarchy」でまだ開いたままにして、「**Window**」ゲームオブジェクトを展開し、「**Glass**」ゲームオブジェクトを選択します。

**2.**「Inspector」で、「Mesh Renderer」コンポーネントを見つけます。

**3.**  「Materials」セクションで「**PortalWindow**」マテリアルをダブルクリックし、「Inspector」でそれを開きます。

[Image: image]

**4.**Material Inspector で「**Shader**」ドロップダウンを選択して、「**Custom**」>「**PortalWindowShader**」を選択します。

[Image: image]

まだ何も変わっていないように見えますが、ポータルウィンドウを意図したように機能させるには不可欠なステップです。

## 5. カスタム URP アセットを割り当てる

Q&A (0)

このプロジェクトは[ユニバーサルレンダーパイプライン](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@latest/)（URP）を使用してビルドされます。これは、Unity プロジェクトで高品質の最適化されたグラフィックスを実現するために使用される、高度にカスタマイズ可能なレンダリングシステムです。URP を使用するときは、[Renderer Feature](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@10.1/manual/urp-renderer-feature.html) を追加することもできます。これは、オブジェクトのレイヤーに基づいて、オブジェクトのレンダリングを制御します。時間を節約するため、これらの Renderer Feature を既に含んでいる事前設定済みの URP アセットが用意されています。それらの Renderer Feature がセットアップされた方法については、後で学びます。

以下の手順に従い、グラフィックスの設定でカスタム URP アセットを割り当てます。

**1.**メインメニューから、「**Edit**」>「**Project Settings**」を選択します。左側のパネルで、「**Graphics**」を選択します。

**2.**スクリプタブルレンダーパイプラインの設定で、オブジェクトピッカー（丸いアイコン）を使用して「**URP_Portal Asset**」を選択します。

[Image: image]

**3.**レンダーパイプラインの変更には非常に長い時間がかかる可能性があることを警告するウィンドウがポップアップする場合があります。「**Continue**」を選択します。

「**Graphics**」の設定で URP アセットを変更するだけでなく、「**Quality**」の設定でもそれを行う必要があります。[「**Quality**」の設定](https://docs.unity3d.com/Manual/class-QualitySettings.html)を使用すると、異なる品質レベルに対して特定の URP アセットを選択でき、プラットフォームごとにデフォルトの品質レベルを割り当てることもできます。

[Image: image]

ただし、このポータルはすべてのプラットフォームにおいてすべての品質レベルで機能する必要があるため、すべての品質レベルに「**URP_Portal Asset**」を設定します。

**4.**「Project Settings」ウィンドウの左側のパネルで、「**Graphics**」を選択します。

**5.**各品質レベルを選択し、各レベルで「**Render Pipeline Asset**」を「**URP_Portal Asset**」に設定します。

## 6. レンダラーのレイヤーを設定する

Q&A (0)

以下の手順に従って、プロジェクトを設定します。

**1.**シーンビューで**ポータル**のプレハブを開きます。

**2.**Project ウィンドウで、検索バーを使用して「**URP_Portal Asset_Renderer**」を見つけて選択します。

[Image: image]

**3.**Inspector の「**Filtering**」セクションで、「**Opaque Layer Mask**」と「**Transparent Layer Mask**」プロパティのドロップダウンを使用して、両方のプロパティで「**PortalWindow**」と「**PortalContents**」レイヤーの選択を解除します。これにより、ポータルウィンドウのペインとポータルのコンテンツがシーンビューに表示されなくなります。

「**Filtering**」セクションは、アプリケーションでレンダリングされるレイヤーを制御します。2 つのカスタムレイヤーの選択を解除すると、ポータルウィンドウとポータルのコンテンツがレンダリングプロセスから除外されます。ポータルウィンドウのフレームはデフォルトレイヤー上にあるため、まだ見ることができます。次に、Renderer Feature を使用して、ポータルウィンドウとそのコンテンツをカスタム動作付きでビューに追加して戻します。

**4.**「**URP_Portal Asset_Renderer**」がまだ選択されている状態で、「**Portal Window (Render Objects)**」Renderer Feature を見つけて展開します。機能の「**Layer Mask**」プロパティを「**PortalWindow**」レイヤーに設定します。このようにすると、半透明のポータルウィンドウがシーンビューに表示されることを確認します。

[Image: image]

時間を節約するため、これらの事前設定済みの Renderer Feature を、提供された URP アセットに組み込みました。新しい Renderer Feature を追加するには、Inspector の下部にある「**Add Renderer Feature**」を選択できます。

**5.**「**Portal Contents (Render Objects)**」 Renderer Feature を見つけて展開した後、その「**Layer Mask**」プロパティを「**PortalContents**」レイヤーに設定します。このようにすると、ポータルのコンテンツがポータルウィンドウを通して見えるようになることを確認します。

## 8. 実際に行われていること

Q&A (0)

このカスタムポータルのレンダリングは、ステンシルと呼ばれる URP の機能に頼っています。**ステンシル**を使用すると、描画できる、または描画できない画面上の領域を指定でき、ポータルやミラーのような効果に最適です。

ステンシルは少し複雑ですが、その仕組みを学びたい場合は読み進めてください。そうでない場合は、このステップをスキップしてかまいません。

#### ステンシルとは？

デジタルステンシルは、鉛筆で図面を描くときに使用したことがあるかもしれない物理的なステンシルとよく似ています。ステンシルは、内部を描画できる領域を定義し、その領域の外側は描画されないようにするものです。ステンシル領域の内部には、どのようなものでも描画できます。

[Image: image]

#### ステンシル領域の定義

ステンシルは、Renderer Feature の「**Overrides**」セクションで設定します。あらためて Portal Window Renderer Feature を確認すると、「**Stencil**」プロパティが有効にされ、「**Value**」が設定されていることがわかります。**1**.

[Image: image]

物理的なステンシルを相互に重ね合わせて使用できるのと同じように、URP でも複数のステンシル レイヤーを使用できます。「**Value**」プロパティは、使用するステンシルの数を制御します。「**Compare Function**」は「**Always**」に設定され、その「**Pass**」プロパティは「**Replace**」に設定されます。詳細については[ステンシルのドキュメント](https://docs.unity3d.com/Manual/SL-Stencil.html)で確認できますが、これらの設定により、ポータルウィンドウのピクセルが最初のステンシルレイヤーに追加されます。

#### ステンシル領域内の描画

ステンシルレイヤー 1 でステンシル領域を定義したら、次のステップは、画面上のステンシル領域内にポータルのコンテンツを描画することです。

**Portal Contents** Renderer Feature の「**Overrides**」セクションを見ると、この機能についても「**Stencil**」プロパティが有効にされていることがわかります。ただし、ここでは、「**Compare Function**」は「**Equal**」に設定されているので、これらのゲームオブジェクトのピクセルは、その定義されたステンシル領域内にある場合にのみ描画されます。

[Image: image]

興味がある場合は、これらのステンシルの設定をいろいろ試してみて、その効果を確認し、ステンシルの動作についての理解を深めてください。

ユーザーは、ポータルを配置できても、その位置が気に入らないかもしれません。または、単に別の場所に新しいポータルを配置したいこともあるでしょう。現在、ユーザーが新しいポータルを配置するには、アプリケーションを完全に再起動するしかありません。平面検出をリセットし、ユーザーが新しいポータルを配置できるようにする手段が、アプリケーション体験内に必要です。以下のガイダンスを使用するとこの課題の完了に役立ちます。

- 新しいリセットボタンと、リセットボタンの機能を管理する新しい Script Machine を作成します。
- リセットボタンが押されたら、**ポータル**ゲームオブジェクトを破棄し、AR Plane Manager を再アクティブ化して、AR Session をリセットする必要があります。領域内の平面検出をリセットするには、「**AR Session: Reset**」ノードを使用できます。AR Session をリセットしないと、AR Plane Manager が再び有効にされたら、それまでに検出された平面がすぐに再び表示されます。

この体験では作成するときに垂直または水平のポータルを選択しましたが、ユーザーが自分でそれを選択できるようにしたらどうでしょう。以下のガイダンスを使用するとこの課題の完了に役立ちます。

- 水平ポータルと垂直ポータルが 1 つずつ含まれる新しい**ポータル**プレハブを作成します。新しいポータルの作成に関するガイダンスについては、これまでのチュートリアルを確認してください。
- デフォルトで、AR Plane Manager の「**Detection Mode**」プロパティを「**None**」に設定します。
- ポータルのスタイル選択を管理するための新しい Script Machine を作成します。
- ボタンが押されたら、「**AR Plane Manager: Set Requested Detection Mode**」ノードを使用して、検出モードを適切に設定します。
- インスタンス化シーケンスでは、「**If**」ノードを使用して、どちらの検出モードが押されたかを調べます。検出モードが垂直の場合は、垂直ポータルをインスタンス化します。検出モードが水平の場合は、水平ポータルをインスタンス化します。
- オプションとして、ユーザーが異なるオプションを選択できるように、シーンを再ロードする「Back」または「Exit」ボタンを作成します。
