<task type="auto">
  <name>Task 1: Build batch extraction orchestrator</name>
  <files>scripts/batch-extract.mjs</files>
  <action>
Create `scripts/batch-extract.mjs` that orchestrates bulk extraction of all manifest URLs. The script must:

**Manifest I/O:**
- Read manifest.json on startup, filter to URLs with status "pending" or "failed" (retry failed ones too)
- Sort filtered URLs by source priority: learn first, then manual, then api (per user decision)
- After each page extraction, update the URL entry in-memory AND write manifest.json to disk (enables kill-and-resume)
- On graceful shutdown (SIGINT/SIGTERM), save manifest before exit

**Concurrency and throttling:**
- Run 10 concurrent page extractions using a semaphore/pool pattern (not Promise.all on entire array)
- Share a single Puppeteer browser instance across all concurrent pages (pass `options.browser` to extractPage)
- Auto-throttle: when a page returns 403 or the error contains "rate" or "throttle", reduce concurrency to 2 and add 30s delay between pages. After 60s of successful extractions, gradually restore to 10.
- Implement exponential backoff for throttle detection: 30s -> 60s -> 120s cooldown periods

**File organization:**
- Derive output path from URL: `content/{source}/{url-path-slug}.md`
  - Source mapping: "learn" for learn.unity.com, "manual" for docs Manual, "api" for docs ScriptReference
  - URL path slug: take URL pathname, strip file extensions, replace `/` with `-`, lowercase
  - Example: `https://learn.unity.com/tutorial/get-started` -> `content/learn/tutorial-get-started.md`
  - Example: `https://docs.unity3d.com/6000.0/Documentation/Manual/UnityManual.html` -> `content/manual/unitymanual.md`
  - Example: `https://docs.unity3d.com/6000.0/Documentation/ScriptReference/MonoBehaviour.html` -> `content/api/monobehaviour.md`
- Create directories recursively as needed (mkdirSync with recursive: true)
- Write markdown content to the derived path
- Store the relative content file path in manifest entry's `contentFile` field

**Content hash deduplication (EXTR-03):**
- After extracting markdown, compute a SHA-256 hash of the content (using node:crypto)
- Before writing the file, check if any previously-extracted URL in the manifest has the same contentHash
- If duplicate found: set status to "duplicate", store contentHash, store `duplicateOf` field pointing to the canonical URL, do NOT write the file
- If unique: write the file, set status to "verified", store contentHash

**Unity version tagging (EXTR-05):**
- Extract Unity version from URL path: `/6000.0/` -> "6000.0", `/6000.1/` -> "6000.1", `/6000.2/` -> "6000.2"
- For learn.unity.com URLs without version in path: scan first 500 chars of markdown for patterns like "Unity 6" or "Unity 2022" or "Unity 6000"
- Store extracted version in manifest entry's `unityVersion` field
- If no version detected, set unityVersion to "unknown"

**Progress reporting:**
- Print a status line every 10 pages: `[1234/46183] Learn: 45% | Manual: 0% | API: 0% | Dupes: 12 | Fails: 3 | Rate: 2.1 pg/s`
- On completion, print summary: total verified, duplicates, failures, elapsed time
- Log individual page results to stdout: `OK 832w content/learn/tutorial-get-started.md` or `FAIL 403 https://...`

**CLI interface:**
- `node scripts/batch-extract.mjs` -- run full extraction
- `node scripts/batch-extract.mjs --source learn` -- extract only learn URLs
- `node scripts/batch-extract.mjs --limit 50` -- extract first N pending URLs (for testing)
- `node scripts/batch-extract.mjs --dry-run` -- show what would be extracted without doing it

**Error handling:**
- Pages that fail after 5 retries: set status to "failed", store error message, increment retryCount
- Pages with insufficient content (<100 words): set status to "insufficient", not retried
- Browser crash: catch, relaunch browser, continue from next URL
- Manifest write failure: catch, log error, continue (don't crash the whole run)
