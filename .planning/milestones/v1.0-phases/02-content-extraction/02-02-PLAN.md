**Dedup report:**
- Count of unique content hashes vs total verified pages
- List any URL that appears as a duplicate target (duplicateOf) more than 5 times (highly duplicated content)

**Version coverage:**
- Count of entries per unityVersion value
- List any entries with unityVersion "unknown"

**Quality spot-check:**
- Pick 5 random verified entries, check that their contentFile exists on disk
- Check that at least one file per source has >200 words
- Check that no verified entry has a null contentHash

**Validation checks (exit code 0 if all pass, 1 if any fail):**
1. No pending URLs remain (100% attempted)
2. Verified + duplicate >= 95% of total (allow up to 5% failures/insufficient)
3. All verified entries have non-null contentHash
4. All verified entries have non-null unityVersion
5. All verified entries have non-null contentFile pointing to an existing file

**CLI:**
- `node scripts/verify-extraction.mjs` -- full report
- `node scripts/verify-extraction.mjs --check` -- just pass/fail validation (for CI-style usage)
- `node scripts/verify-extraction.mjs --failures` -- list all failed URLs with error messages

<task type="auto">
  <name>Task 2: Run full extraction by source in priority order</name>
  <files>scripts/batch-extract.mjs</files>
  <action>
Execute the full extraction in source-priority order. This is a long-running task.

**Execution strategy:**
1. Run Learn source first (13K URLs, most skill-relevant):
   `node scripts/batch-extract.mjs --source learn`
   - Expected duration: ~2-4 hours at ~2 pages/sec with 10 concurrency
   - Monitor for throttle events in stdout output
   - If the script crashes or is interrupted, it resumes automatically on re-run

2. After Learn completes, run Manual source (3.5K URLs):
   `node scripts/batch-extract.mjs --source manual`
   - Expected duration: ~30-60 min

3. After Manual completes, run API source (29K URLs):
   `node scripts/batch-extract.mjs --source api`
   - Expected duration: ~4-8 hours

4. After each source completes, run `node scripts/verify-extraction.mjs` to check progress

**Monitoring during extraction:**
- Watch for sustained throttle messages (auto-throttle should handle temporary rate limits)
- Watch for browser crash/restart messages (should auto-recover)
- If a source consistently fails (>10% failure rate), investigate and fix the extraction logic in batch-extract.mjs before continuing

**Handling persistent failures:**
- After all 3 sources complete, check for failed URLs: `node scripts/verify-extraction.mjs --failures`
- If failures are HTTP errors (403, 404): these are legitimate unreachable pages, acceptable
- If failures are timeout errors: run a retry pass with `node scripts/batch-extract.mjs --retry-failed` (re-attempts failed URLs)
- If failures are extraction bugs: fix batch-extract.mjs or extract-page.mjs and re-run

**Fix issues as they arise:**
- If the content file paths have collisions (two URLs mapping to same slug), add a counter suffix or use more of the URL path
- If throttle detection is too aggressive (treating non-throttle errors as rate limits), adjust the detection logic
- If Puppeteer memory grows unbounded with many pages, add periodic browser restart (every 500 pages)
