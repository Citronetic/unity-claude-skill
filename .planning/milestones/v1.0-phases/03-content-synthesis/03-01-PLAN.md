Create `scripts/build-topic-map.mjs` that reads `manifest.json` and assigns every verified URL entry to one of 16 synthesis topics (or "skip").

The 16 reference file topics (from Phases 5-8 of ROADMAP.md):
1. project-setup (Unity Hub, project creation, folder structure, .gitignore, LFS, meta files)
2. editor-workflows (scene management, GameObjects, Prefabs, Inspector)
3. scripting-fundamentals (MonoBehaviour lifecycle, components, events, serialization)
4. scripting-patterns (ScriptableObjects, coroutines, async/await, deprecated pattern steering)
5. physics (Rigidbody, Colliders, triggers, raycasting, 2D and 3D)
6. input-system (New Input System, Input Actions, bindings, PlayerInput, touch/mobile)
7. testing (Unity Test Framework, EditMode, PlayMode, NUnit)
8. rendering-2d (sprites, SpriteRenderer, 2D lighting, tilemaps)
9. rendering-3d (materials, lighting, cameras, URP setup)
10. ui-toolkit (UI Toolkit, uGUI legacy, runtime UI, editor UI)
11. animation (Animator, state machines, clips, procedural animation)
12. audio (AudioSource, AudioListener, AudioMixer, compression)
13. build-deploy (build settings, player settings, platform switching, IL2CPP vs Mono)
14. cli-tools (command-line arguments, batch mode)
15. asset-pipeline (import settings, asset management, Addressables)
16. mobile-platform (mobile optimization, touch input, screen resolution, performance)

Topic assignment logic (in priority order):
- **API reference pages** (source=api-reference): Assign by parsing the API class name from the filename. Map known Unity namespaces to topics:
  - `Physics*`, `Rigidbody*`, `Collider*`, `Joint*` -> physics
  - `Input*`, `Gamepad*`, `Keyboard*`, `Touch*`, `Pointer*` -> input-system
  - `AudioSource*`, `AudioListener*`, `AudioMixer*`, `AudioClip*` -> audio
  - `Animator*`, `Animation*`, `AnimationClip*`, `AnimatorController*` -> animation
  - `Camera*`, `Light*`, `Material*`, `Shader*`, `Render*`, `URP*` -> rendering-3d
  - `Sprite*`, `SpriteRenderer*`, `Tilemap*`, `SpriteMask*` -> rendering-2d
  - `UIElements*`, `VisualElement*`, `UIDocument*`, `IMGUI*`, `GUI*`, `Canvas*`, `Button*`, `Text*`, `Image*` (UI context) -> ui-toolkit
  - `MonoBehaviour*`, `Component*`, `GameObject*`, `Transform*`, `Coroutine*`, `ScriptableObject*` -> scripting-fundamentals OR scripting-patterns
  - `BuildPipeline*`, `BuildSettings*`, `PlayerSettings*`, `EditorBuildSettings*` -> build-deploy
  - `AssetBundle*`, `Addressables*`, `AssetDatabase*`, `AssetImporter*` -> asset-pipeline
  - `EditorApplication*`, `Editor*`, `MenuItem*`, `SerializedProperty*` -> editor-workflows
  - `Application*`, `SystemInfo*`, `Screen*` -> mobile-platform (if mobile-related) or project-setup
  - `TestRunner*`, `Assert*`, `UnityTest*` -> testing
  - Everything else in API -> "skip" (will be available for verification lookups but not synthesized)
- **Manual pages** (source=manual): Assign by filename keywords using similar keyword-to-topic mapping. Manual pages have descriptive filenames like `2d-physics-*.md`, `urp-*.md`, `packages-*.md`.
- **Learn tutorial pages** (source=learn-tutorial, learn-project, learn-course): Assign by filename + content keywords. Many will map to scripting-fundamentals or project-setup.
- **Best practice pages**: Map by filename to relevant topic.
- **Non-English tutorials** (filenames containing Korean/Japanese/Spanish patterns like `-jp.md`, `-kr.md`, `configuracion`, `gyoyug`): Assign to "skip".
- **Insufficient/failed/pending pages**: Assign to "skip".

**Part A: API Name Index**

Create `scripts/build-api-index.mjs` that scans all `content/api/*.md` files and extracts the primary API name (class, method, property, or enum) from each file. The API name is typically in the first H1 heading or derivable from the filename.

For each API page, extract:
- `name`: The fully qualified API name (e.g., `Rigidbody.AddForce`, `Physics.Raycast`)
- `shortName`: Just the member name (e.g., `AddForce`, `Raycast`)
- `className`: The parent class (e.g., `Rigidbody`, `Physics`)
- `contentFile`: Path to the extracted markdown file

Output `synthesis/api-index.json`:
```json
{
  "generatedAt": "ISO timestamp",
  "totalAPIs": N,
  "byClass": {
    "Rigidbody": ["AddForce", "velocity", "mass", ...],
    "Physics": ["Raycast", "RaycastAll", ...],
    ...
  },
  "byName": {
    "Rigidbody.AddForce": "content/api/rigidbody.addforce.md",
    ...
  }
}
```

This index enables Plan 02/03 to verify any API name mentioned in synthesis output against the extracted docs in O(1) lookups.

Performance note: There are ~27K API files. Read filenames first (they encode the API name as `classname-membername.md` or `classname.membername.md`). Only open files when the filename is ambiguous. Process in streaming fashion, not all at once.

Format as a structured reference:
```markdown
# Deprecated Patterns Reference

## API Deprecations (Unity 6.x)

| Deprecated | Replacement | Since | Topic |
|-----------|-------------|-------|-------|
| ExecuteDefaultAction | HandleEventBubbleUp | Unity 6.0 | ui-toolkit |
| VisualElement.transform | VisualElement.style.translate/rotate/scale | Unity 6.2 | ui-toolkit |
| SetupRenderPasses | RecordRenderGraph | Unity 6.2 (URP) | rendering-3d |
| ...

## Anti-Patterns (Do Not Use)

| Pattern | Why Not | Use Instead | Topic |
|---------|---------|-------------|-------|
| OnGUI() | Legacy immediate-mode GUI | UI Toolkit | ui-toolkit |
| Resources.Load() | Not scalable, no async | Addressables | asset-pipeline |
| old Input Manager | Legacy system | New Input System | input-system |
| WWW class | Deprecated | UnityWebRequest | scripting-patterns |
| PlayerPrefs for save data | Not for complex data | JSON serialization | scripting-patterns |
| UNet | Deprecated networking | Netcode for GameObjects | skip (v2) |
| UnityScript/Boo | Removed from Unity | C# only | skip |
| Built-in RP (for new projects) | Legacy pipeline | URP | rendering-3d |
```

Also scan `content/manual/upgradeguide*.md` files for additional deprecation entries. Each row should list which synthesis topic it applies to.
