<task type="auto">
  <name>Task 1: Test Chrome automation on Unity tutorial pages and resolve CN site behavior</name>
  <files>scripts/browser-test.mjs, docs/cn-site-resolution.md</files>
  <action>
This task has two sequential parts:

**Part A: CN site resolution**
1. Use chrome-devtools-mcp (or WebFetch as a quick pre-check) to attempt accessing `https://unity.com/cn/learn/get-started`
2. Also attempt `https://learn.unity.com` (the English tutorial hub)
3. Also attempt `https://docs.unity3d.com/Manual/` (the Unity Manual)
4. Document what happens with each URL: HTTP status, whether content loads, whether it redirects, whether it returns Chinese or English content, whether it blocks automation
5. Write findings to `docs/cn-site-resolution.md` with a clear final decision:
   - Per user decision: English is the final language, learn.unity.com is primary, docs.unity3d.com is supplementary
   - CN site is deprioritized -- only note if it works, do not invest time debugging it
   - If CN site returns 403 or blocks automation, document and move on

**Part B: Chrome automation proof-of-concept**
1. Try chrome-devtools-mcp first (more granular control per user decision). If it has issues, fall back to `claude --chrome`
2. Navigate to a specific Unity Learn tutorial page, e.g., `https://learn.unity.com/tutorial/get-started-with-unity`
3. Extract the rendered text content (not raw HTML)
4. Confirm the extracted content has >100 words of substantive text
5. Create `scripts/browser-test.mjs` as a Node.js script documenting the exact browser automation approach that works:
   - Which tool (chrome-devtools-mcp vs claude --chrome)
   - The navigation sequence
   - How to extract text content
   - Retry logic: 5 retries with 10-second waits (per user decision)
   - A function that takes a URL and returns extracted text content
6. Create the `content/` directory with a `.gitkeep` file for the future per-page markdown files

The script should be executable and serve as the reference implementation for Phase 2's bulk scraping.
